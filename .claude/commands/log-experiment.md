이번 세션에서 수행한 실험을 **3계층 구조(STATE/LOG/ARCHIVE)**에 맞게 정리해줘.

> **기록 위치 (중요)**: 개별 실험의 **전체 서술**은 `EXPERIMENTS_LOG.md`(LOG)에 추가한다. `EXPERIMENTS.md`(STATE)에는 **빠른참조 표에 1행만**(Epoch 열 포함) 추가하고, 확정 결론이 바뀐 경우에만 "이월 핵심사실"을 갱신한다. STATE는 ~150줄 상한을 유지하므로 전체 서술을 STATE에 쓰지 않는다.

1. `EXPERIMENTS.md`(STATE)의 "빠른 참조" 표에서 마지막 Exp 번호를 확인하고 다음 번호를 부여한다(Exp-001~130은 PHASE2_EXPERIMENTS.md 아카이브, Exp-131~은 `EXPERIMENTS_LOG.md`, 신규는 그다음 번호로 이어간다).

1-b. **이번 실험의 코드 세대(Epoch)를 판정한다.** STATE 상단 "코드 세대(Epoch)" 절을 기준으로, *측정 대상 코드(브랜치)*가 어느 epoch인지 결정해 빠른참조 행의 Epoch 열에 적는다(현재 master=E1, `exp/meta-token-suppress`=E2 후보). 이번 변경이 **실패 모드를 바꾸는 구조적 변경(언어고정·비음성억제·디코더/VAD 파이프라인 등)을 master에 머지**한 것이면, STATE의 epoch 마커를 +1 올리고 이전 세대 파라미터 결론에 `[E?·재검증]`을 부여한다(major 방향 전환이므로 사용자에게 보고).

1-c. **측정 언어모드는 항상 `auto`다(CLAUDE.md §3.2).** kor1~3·eng1을 포함한 모든 테스트/held-out 측정이 `--lan auto`로 수행되므로, 빠른참조 행의 **언어모드 열에는 `auto`를 고정 기입**한다. ko/en 세션 고정 기능 자체를 검증한 실험(예외적으로 `--lan ko`/`--lan en` 사용)만 그 값을 기입하고 LOG 서술에 예외 사유를 명시한다.

2. 이번 세션에서 수정한 코드 파일, 변경 이유, 벤치마크 결과를 바탕으로 아래 필드를 채운다:
   - 날짜 (오늘 날짜)
   - 측정 언어모드 (기본 `auto` — 1-c 참조, ko/en 세션고정 검증 등 예외 시에만 다른 값)
   - 가설 (왜 이 변경이 필요했는가)
   - 변경 내용 (파일경로:라인번호 형식으로)
   - 테스트 설정 및 명령어
   - 정량 결과 (WER, F1 — 이전 Exp 대비 비교 포함)
   - **전사 내용 정성 분석** (아래 §A 참조 — `### 분석` 섹션으로 작성)
   - 채택 조건 판정 (①max 미회귀 ②median 개선)
   - 결론 (채택 / 기각 / 수정 예정)
   - 다음 가설

   위 §2의 전체 서술(가설·변경·테스트설정·결과표·`### 분석` 정성분석·채택 판정·다음 가설·JSON 경로)은 **`EXPERIMENTS_LOG.md`의 맨 아래에 `## Exp-N` 블록으로 추가**한다(앞에 `---` 구분선). LOG 상단의 작성 형식·Exp↔Epoch 안내를 따른다.

3. `EXPERIMENTS.md`(STATE)의 "빠른 참조" 표 **상단에 한 줄 추가**한다 — `| Exp-N | <Epoch> | <언어모드> | 날짜 | 변경 | bong1 med | ytn2 med | sbs1 med | 판정 |` 형식(언어모드 열은 1-c 기준 기본 `auto`). kor1~3을 대상으로 한 실험이면 LOG 서술에 kor1/kor2/kor3 median을 함께 남긴다. 확정 결론(파라미터 트레이드오프·구조 사실)이 바뀌었으면 STATE "이월 핵심사실"의 해당 항목도 epoch 태그와 함께 갱신한다.

4. 작성한 내용(LOG 블록 + STATE 빠른참조 행)을 출력하고 수정할 부분이 있는지 확인을 구한다.

벤치마크 결과 파일이 있으면 (`.omc/benchmarks/` 디렉토리) 해당 파일을 읽어 정량 수치를 정확히 옮긴다.

## §A — 전사 내용 정성 분석 작성 방법

**목적**: 수치(WER/F1)만으로는 실패 원인을 알 수 없다. 실제 전사 텍스트와 정답 스크립트를 직접 대조해 구체적 실패 모드를 서술한다.

### 입력 데이터
`.omc/benchmarks/` 에서 이번 실험의 eval JSON 파일을 읽는다.
- `files[]` 배열: 각 항목에 `audio_file`, `transcription`(전사 전문), `reference`(정답 전문) 포함.
- 채택 확정(3회) 측정 시 파일당 3개 항목 존재: **median WER 회차를 대표로 대조**하고, **max WER 회차는 catastrophic 패턴 확인**용으로 훑는다. 스크리닝(1회)은 단일 수치를 방향 신호로 기록한다.
- JSON이 없으면(저장 누락) 사용자에게 재측정 또는 전사 텍스트 제공을 요청한다.

### 분석 방법
`transcription` 과 `reference` 를 직접 읽고 아래 실패 모드를 확인한다.
해당하는 항목만 기록하고, **구체적 텍스트 인용을 1개씩 포함**한다(추측·일반화 금지):

| 실패 모드 | 확인 대상 |
|-----------|-----------|
| **비언어 토큰** | `(웃음)` `(laugh)` `(박수)` `(applause)` `(음악)` 등 |
| **깨진 특수기호** | 열린 괄호 `(`, 따옴표 깨짐 등 |
| **환각 폭주** | 동일 단어·구 반복, 무의미 텍스트 체인 |
| **단어 유실·잘림** | 정답엔 있는데 전사엔 없는 단어/구 |
| **코드스위칭 실패** | 한↔영 경계 누락·오인식 (ytn2 핵심 지표) |
| **화자 혼동·경계 오류** | 다화자 환경(bong1)에서 화자 전환 누락 또는 잘못 분리 |

### 출력 형식
`### 테스트 세트 결과` 표 **직후**, `### 채택 (조건) 판정` **직전**에 삽입:

```markdown
### 분석 (전사 내용 정성 대조)

**bong1** (R_median 기준):
- **비언어 토큰**: 전사 `"(웃음) 그래서 어…"` / 정답 `"그래서 어…"` — 웃음 구간 3회 발생.
- **환각 폭주**: 전사 `"네 네 네 네 네"` / 정답 `"네."` — 웃음 끝 무음 구간에서 촉발.

**ytn2** (R_median 기준):
- **코드스위칭 실패**: 전사 `"그건 trust 있는"` 누락 / 정답 `"그건 trust 있는"` — 한→영 전환 구간 잘림.

**sbs1** (R_median 기준):
- 주요 실패 없음. 영어 인용구 처리 정상.

**이번 변경 영향**: lang-set 마스킹이 bong1 웃음 구간에서 비언어 토큰 대신 환각형 한글 토큰을 강제 출력 → WER 악화. sbs1은 non-Hangul 토큰 억제 효과로 개선.
```

- 파일별로 구분해 서술한다(bong1 / ytn2 / sbs1 순).
- 마지막에 **이 실험 변경이 위 실패 모드를 개선·악화·무관하게 했는지** 1~2줄로 요약한다.
- 인용은 짧게 (`"…"` 앞뒤 생략 허용), 길이 30자 이내 권장.
- 발견된 항목이 없는 파일은 "주요 실패 없음"으로 명시한다.
