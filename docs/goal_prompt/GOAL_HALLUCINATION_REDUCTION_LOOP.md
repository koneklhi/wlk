- 매 이터레이션마다 진행 리포트를 갱신한다(§6). 이것이 아침에 사용자가 읽는 유일한 산출물이다.

## 1. 목표 · 제약

- **목표**: 환각(발화되지 않은 텍스트 삽입) **빈도를 조금이라도 줄인다** — 완벽 제거가 아니라 계열별 발생률 하락.
- **최우선 제약: 다른 곳 전사에 영향을 주지 않는다.** 모든 변경은 (a) 좁은 발동 조건 + 롤백 플래그, (b) 짝지음 A/B로 비발동 회차 = 동일 코드임을 보장, (c) 정상 단어 유실 0(특히 침묵 직전 정상 꼬리), (d) Case B(단어 중간 분절) 0 을 만족해야 한다. **환각 1건을 줄이려고 정상 전사 1건을 희생하지 않는다.**
- **일반화 원칙(§3.8)**: 데이터 특화 하드코딩 금지. 어휘 블랙리스트("감사합니다" 금지어 등)는 최후 수단이며 이번 루프에서는 시그니처(정렬 타임스탬프·VAD 상태·경계 이벤트) 기반 접근만 쓴다.
- **이번 루프에서 master 머지 금지.** 모든 코드는 워크트리 + `exp/` 브랜치에 커밋만 한다. 채택 확정 게이트(`--repeat 3`)를 통과한 후보는 "채택권고·머지 대기"로 기록한다(§4 목표 필수 기능 질의 절차의 야간 버전).

4. **분석** — 정량(표적 지표 우선, WER/F1은 스크리닝=방향신호) + 정성(전사 대조: 환각 소멸 여부·신규 부작용·Case B). 전사 중복을 보면 결함 단정 전에 재디코딩 아티팩트 판별 신호(시각 겹침+refresh 유무)로 1차 선별, 실발화 가능성은 "아침 확인 요청"으로 기록.
5. **기록** — 진행 리포트 갱신(§6) + 측정을 동반한 이터레이션은 `/log-experiment`(Exp-201부터 이어서, 측정 언어모드 명시).
6. **다음 결정** — 성공: 같은 항목 심화 또는 다음 항목. 실패: 원인 분석 기록 후 각도 변경 또는 다음 항목. **어느 쪽이든 즉시 다음 사이클 시작.**

## 5. 측정 규율

- 경로 C만, 측정은 **메인 세션에서 직접**(서브에이전트 위임 금지 — 조기 정지 전력). 측정 중 워크트리 코드 mutation 금지.
- **측정 전 확인**: 다른 세션 VBCable 사용 겹침(포트 8901 점유·python 프로세스), 결과 provenance 첫 줄 `vbcable=ok` 육안 확인.
- 표준 명령(`.claude/commands/eval.md` 정본; 측정 UI = 배포 UI 기본값, 사전에 `cd frontend/app; pnpm build` 필요):

```powershell
$env:PYTHONIOENCODING = "utf-8"; $ts = Get-Date -Format "yyyyMMdd_HHmm"
# ko run (kor1~3)
.venv\Scripts\python.exe scripts/eval.py --model-dir whisperlivekit/model/whisper-large-v3-turbo `
  --files test_data/kor1.wav test_data/kor2.wav test_data/kor3.wav --lan ko `
  --diarization --sortformer-model whisperlivekit/model/sortformer-4spk-v2.nemo `
  --compression-ratio-threshold 3.0 --trace-tokens `
  --output .omc/benchmarks/eval_${ts}_<라벨>.json
# auto run (sbs1/bong1/ytn2) — --files/--lan만 교체. 언어모드 섞인 run 금지(run 분리).
```

- 2계층: 스크리닝 `--repeat 1`(방향신호), 채택권고 후보만 `--repeat 3`(fail-fast 금지·max 우선). 채택 게이트 순서 = 화자분리 F1 worst 미회귀 → WER max 미회귀 → WER median → 문장분리 F1. Case B는 수치 무관 hard-fail.
- 짝지음 A/B는 **발동 카운트로 귀속**한다 — 게이트 미발동(0-firing) 회차는 동일 코드 = 노이즈 대조군. 발동이 희소하면 "이익 귀속 불가(판단 유보)"가 정상 결론이다.

## 7. 안전 규칙 · 복구 플레이북

### 7-1. 워크트리 · 브랜치

- **main 브랜치 위 코드 편집 금지** — 작업마다 `exp/hallu-*` 브랜치 + 워크트리. `.venv`는 메인에 Junction(`mklink /J .venv ..\..\.venv`), `test_data/*.wav`·모델·sortformer.nemo 하드링크 필요(누락 시 returncode=3 — venv 오염 속단 금지, 서버 로그부터 읽기).
- 워크트리 측정은 cwd=워크트리에서, import 경로가 워크트리로 해석되는지 확인 후.
- **워크트리 삭제 전**: ① `.omc/` 산출물(전사·JSON·로그)을 메인으로 복사 ② `cmd /c rmdir .venv`로 Junction 먼저 해제(따라가서 메인 .venv 삭제 사고 2회 전력).

### 7-2. uv 가드레일 (공유 .venv 오염 = 루프 전멸)

`uv run`·`uv pip`·`uv add/remove/lock/venv`·extras 없는 `uv sync` **절대 금지**. lint는 `.venv\Scripts\ruff.exe` 직접 호출, 테스트는 `.venv\Scripts\python.exe -m pytest`. 의존성 변경은 이번 루프에서 불필요 — 필요해 보이면 그 작업을 스킵하고 기록.

### 7-3. 에러 복구

- **서버 기동 실패/returncode=3**: 서버 로그 먼저(모델 경로·하드링크·포트 충돌). 포트 8901 점유 시 잔존 프로세스 종료 후 재시도.
- **VBCable 무음/100% WER/분산 폭증**: 케이블 사망 의심 — `verify_loopback` 진단, Audiosrv 재시작 시도. 복구 불가(재부팅 필요)면 측정 불가 모드로 전환: 계측 코드·유닛테스트·기존 로그 재분석·설계 문서 작업을 진행하며 30분 간격 재확인. **측정 실패를 코드 결함으로 오귀속 금지**(하니스 버그는 즉시 중단·수정이 원칙이나, 하드웨어 블록은 우회).
- **측정 도중 GPU 경합 의심**(디코딩 stall·로그 크기 급감): 해당 회차 폐기 표기 후 재측정 1회. 반복되면 리포트에 기록하고 측정 밀도를 낮춘다(파일 수 축소).
- **pytest 기존 실패 발견**: plain master 단독 실행과 대조해 이번 변경 무관이면 기록만 하고 진행.

### 7-4. 절대 금지 (알려진 막다른 길 — 시간 낭비 방지)

- 경계 재디코딩/flush 계열(Exp-193/194 — 2회 기각·재시도 금지 명문), 출력 후처리 반복필터로 필러 억제(Exp-163), no_speech 게이팅 전 계열(Exp-164/165 — turbo no_speech 헤드 degenerate 확정), VAC 임계 상향(Exp-164).
- ytn2 "한국군 사성자…"·"상당한.. 상당한" 구간은 실발화(사용자 청취 확정) — 반복 억제 근거로 사용 금지.
- held-out(ytn1/eng1/kinno)을 튜닝·조건 도출에 사용 금지(검증 단회만).
