# 한국어 전사 진단: 침묵 후 유실 + 중간 단어 유실 (2026-07-22)

## 배경

배포 PC 정성 테스트에서 사용자가 보고한 두 가지 증상:
1. **BUG A**: 녹음 시작 직후 첫 발화, 또는 침묵이 어느 정도 길었다가 재개되는 발화에서 전사가 바로 되지 않고 날아감.
2. **BUG B**: 한국어 연속 발화 도중 일부 단어가 중간에 유실됨.

이번 세션 목적: **코드 수정 없이** 개발 PC에서 kor1/kor2/kor3/sbs1 각 5회 반복 측정 + `--trace-tokens` 상세 로그로 두 증상을 재현·귀속하고, 원인 후보를 기록해 다음 단계(Fable 모델 기반 해결책 탐색)에 인계한다. **채택/기각 판단이나 코드 수정은 이번 세션 범위 밖.**

## 정성 분석 — 원인 귀속

4개 파일(각 5회) 전사↔정답 대조 + `--trace-tokens` 로그 상관분석을 서브에이전트 4개에 분담(파일당 1개)해 수행했다. 핵심 발견은 **BUG A와 BUG B가 실제로는 각각 단일 메커니즘이 아니라 몇 갈래로 갈라진다**는 것.

### BUG B (중간 단어 유실) — 주 원인 1건, 매우 재현성 높음

**`[UTF-8 Fix] Dropping N incomplete tokens after 2 retries (won't resolve)`** (`whisperlivekit/simul_whisper/align_att_base.py`의 UTF-8 재조립 로직).

스트리밍 디코드 배치 경계에 멀티바이트 한글 문자가 걸리면 `[UTF-8 Filter] Skipping incomplete (held for retry): ' 해�'` 형태로 보류되고, **재시도 2회 안에 완성되지 않으면 그 글자가 속한 단어 전체가 재시도 없이 조용히 버려진다.**

- **kor2**: 5회 중 3회(R1/R3/R5)에서 발동, 매번 정확히 같은 두 지점("보장하고 예비", "로봇 등 유무인")에서 단어가 사라짐. drop 로그 이벤트와 전사 유실이 **1:1 대응** — 발동 없는 R2/R4는 두 구간 모두 정상.
- **kor3**: 5회 중 4회에서 세션 초반 "해역 함대 사이" 구간에 동일 필터 발동, 매번 같은 어절 유실/왜곡.
- **sbs1**: 5회 중 2회(R4/R5)에서 "한반도 동", "전략적" 단어가 동일 메커니즘으로 유실.

세 파일에서 독립적으로 같은 코드 경로가 지목됐고, drop 로그와 유실 위치가 항상 일치한다 — **가장 확실하고 재현성 높은 BUG B 원인**. 재시도 횟수(2회)나 재시도 방식(다음 배치까지 기다리지 않고 포기)이 개선 표적 후보.

### BUG A (침묵 후/세션 시작 유실) — 최소 3~4개 서로 다른 메커니즘이 섞여 있음

1. **긴 침묵 → 컨텍스트 전체 폐기 → 재개 첫 단어 왜곡** (kor1에서 가장 뚜렷): `[EndSilence] branch=long` → `[RefreshSegment] complete=True discarded=X kept=0.00s`로 `state.segments`·컨텍스트가 통째로 비워짐. 그 직후 **컨텍스트 없이** 디코딩되는 첫 단어가 5회 전부 왜곡됨(kor1 "순서는"→"성선을/순선을/스선을×2/수선을", 같은 침묵 지점에서 5/5 재현). 단, 같은 파일의 다른 침묵 지점(2번째 장묵묵)은 5회 모두 정상 복구 — 어떤 침묵 지점에서 터지는지는 회차마다 다소 다름.
2. **세션 시작 자체가 `branch=long`으로 분류돼 첫 단어 디코딩 전에 리셋** (kor3 R3): 다른 4회는 개시 침묵이 `branch=none`(1.95~2.17s)인데 R3만 `branch=long`(2.02s)으로 분류돼 리셋이 먼저 발동, 첫 문장이 통째로 왜곡됨.
3. **화자/언어 eager 재감지 실패 → 꼬리 보존 없는 전체 폐기** (sbs1 R3): 정상 회차는 언어전환 경계에서 `eager=ko, eager_applied=True, kept=1.46~1.70s`로 꼬리를 보존하는데, R3만 `eager_applied=False`가 나며 `kept=0.00s`로 전체 폐기 — 그 구간 오디오("이번 강연의")가 디코더에 아예 도달하지 못함.
4. **컨텍스트 트림 직후 emit 스트림 동기화 버그** (sbs1 R1/R5): 로그상 디코더는 정답 단어("사령관은")를 실제로 만들어냈는데, 트림 이후 emit 시퀀스가 그 토큰을 건너뛰고 다음 토큰으로 넘어감 — 오디오/디코딩 문제가 아니라 **커밋 시퀀스 재동기화 버그**로 보임.
5. 반대로 kor2는 같은 종류의 `RefreshSegment discarded=11~15s` 이벤트가 5회 다 발생하지만 전부 **무해**했다 — `[TokenTrace]`로 추적하면 폐기 시점 이전에 해당 문장 단어가 이미 전부 emit 완료된 상태였음. 즉 **"긴 침묵 → 폐기"가 발동해도, 폐기 시점이 emit 완료 이후냐 이전이냐에 따라 실제 유실 여부가 갈린다.**

### 기타 발견 (참고)

- **Case B(단어 중간 분절)**: 이번 라운드 20회 중 1건만 확인(kor1 R3, "보여"/"주고" 분절) — 스퓨리어스 `speaker_change` 트리거와 동시 발생. 과거 Exp-190(SILENCE_HARD_SECS 문법-조건부화)이 대부분 해소한 것으로 보임.
- **스퓨리어스 `speaker_change` 발동**: 단일 화자인 kor1~3에서 근거 없이 화자전환 트리거가 간헐 발동 — kor1의 최악 두 회차(R3 32.2%, R4 35.1%)는 이 오탐과 동반된 구절 반복/환각이 WER 악화의 상당 부분을 차지.
- **침묵 경계 환각**: sbs1의 KO→EN 경계에서 "사태라" 필러가 5회 중 3회 삽입(QualityGate logprob 문턱을 겨우 통과하거나 통과 못해도 일부 노출). kor3도 "감사합니다"/자막 크레딧류 환각이 2회 관찰. 유실의 반대 방향(불필요한 삽입)이라 별도 원인 계열로 분리해 봐야 함.
- **kor3 R4 = GPU 병목 회차(제외 확정)**: WER 68.2%로 찍혔지만 §정량 결과에 기술한 대로 GPU 기아로 디코딩이 오디오 중반(t_abs≈57.7s/126s)에서 멈춘 회차 — 사용자 확인(측정 중 다른 작업의 GPU 점유 시점 존재)으로 STT 품질 근거에서 제외. kor3 정량은 N=4 기준으로 읽을 것. 단 R4의 **서두 유실 패턴 자체는 다른 4회와 동일**했으므로(BUG A 5/5 재현 결론에는 영향 없음) 정성 결론은 유지.

## 근본원인 확정 — 코드·로그·토크나이저 3중 검증 (2차 분석)

### BUG B: 한글 바이트 분절 + hold-retry 전제 붕괴 (확정)

**토크나이저 실측**: `" 보장"` = 토큰 `[7842, 252, 98]`
- `7842` = `b' \xeb\xb3\xb4\xec'` = `" 보"` + **'장'(3바이트 `\xec\x9e\xa5`)의 첫 바이트**
- `252` = `b'\x9e'` (장의 둘째 바이트 단독), `98` = `b'\xa5'` (셋째 바이트 단독)

즉 Whisper BPE는 한글 1글자를 최대 3개 토큰에 바이트 단위로 흩뿌린다. AlignAtt 스트리밍은 attention이 확신하는 토큰까지만 배치별로 커밋하므로 **커밋 경계가 글자 중간에 떨어지는 것 자체는 구조적으로 정상**이며, 이를 복구하는 것이 `align_att_base.py`의 hold-retry(`_handle_pending_tokens`, `MAX_PENDING_RETRIES=2`)다.

**실패 시퀀스 실측** (kor2 R1 로그 L9707-9834 + L9956-10137):
1. 배치 N이 `[..., 7842]`에서 끊김 → 마지막 단어 `' 보�'` → emit 스킵, hold(retry 1).
2. 다음 배치: prepend 후에도 `' 보�하고'` — 재디코딩이 뒷바이트(252, 98)를 held 프리픽스에 이어 내놓지 않고 다음 어절로 건너뜀 → retry 2.
3. 그 다음 배치도 미완성 → **`[UTF-8 Fix] Dropping ... won't resolve` — 앞바이트 폐기**.
4. 이후 디코더가 고아 뒷바이트 `252`(`'�'`)를 단독 방출 → 앞바이트가 이미 없으므로 영원히 미완성 → **2회 재시도 후 그것도 폐기** (L9956-10137).
5. 결과: "보장하고 예비" 전사에서 증발. Dropping 이벤트↔유실 위치 1:1 대응(R2/R4는 이벤트 0건·구간 무결).

**전제 붕괴가 핵심**: hold-retry는 "다음 배치의 첫 새 토큰들이 held 바이트의 연속"이라고 가정하지만, 재디코딩은 그 제약이 없다(컨텍스트에서 held 토큰이 빠진 채 다시 디코딩되므로 attention이 그 구간을 지나쳐 버리면 완성 바이트는 영원히 안 온다). "retry"가 실제로는 같은 디코드의 재시도가 아니라 **무제약 미래 디코드가 우연히 맞아떨어지길 기다리는 것**이다.

**부수 결함 2건**:
- `_handle_pending_tokens`는 `split_words[-1]`(말미)만 검사 — **중간에 낀 미완성 조각은 재시도 없이 즉시 유실**(emit 스킵 + pending 미등록).
- `Output: 보�하고`가 L867-869에서 `state.tokens`(디코더 컨텍스트)에 커밋됨 — **깨진 바이트가 출력에선 걸러지지만 컨텍스트에는 들어가 후속 디코딩을 오염**(kor3 R3 컨텍스트 덤프 `" 해� 해� � 해�대 사이 현 구�"` → 후속 "현성하겠습니다" 붕괴로 실증).

영어는 ASCII 1바이트라 이 경로가 구조적으로 불가능 — **한국어 전용 실패 모드**인 이유.

### BUG A: "긴 침묵(≥2s) = 완전 리셋" 설계의 콜드스타트 비용 (확정) + 파생 경로

**리셋 경로** (`backend.py:352-408` `end_silence`): `silence_duration >= MIN_DURATION_REAL_SILENCE(=2s)` → `refresh_segment(complete=True)` (`align_att_base.py:185-233`) → `init_tokens()` + `init_context()` + `segments=[]` — **오디오 버퍼·디코더 토큰 히스토리·텍스트 컨텍스트 전부 폐기**. 설계 의도는 침묵 너머 컨텍스트 이월로 인한 환각 루프 방지 + (auto 세션) 언어 재감지 기회 확보. ko 고정 세션도 언어만 유지될 뿐(`backend.py:386-388`) 컨텍스트/버퍼 폐기는 동일하게 수행된다.

**콜드스타트 1차 피해 — 재개 첫 단어 왜곡**: 리셋 직후 재개 발화의 첫 단어는 (a) 텍스트 컨텍스트 0, (b) 스트리밍 특성상 ~0.5s 남짓의 부분 오디오만으로 디코딩된다. LM prior가 없어 음향 유사 오답에 그대로 확정 — kor1 "순서는"이 5/5 회차 **전부, 같은 지점에서, 매번 다른** 음향 유사 오답(성선을/순선을/스선을×2/수선을)이 된 것이 직접 증거. 세션 맨 처음도 동일 상태(kor3 R2 "태국은": 0.24~0.72s 오디오 그리디 첫 토큰 → 오답이 컨텍스트가 되어 문장 전체에 전파).

**콜드스타트 2차 피해 — QG 연쇄로 통째 소실("날라감")**: 콜드스타트 출력이 저품질이면 QualityGate가 억제하고, `quality_gate_reset_after=3`(config.py:26) 연속 억제 시 `_on_quality_suppressed`(align_att_base.py:1065-1086)가 **다시** `refresh_segment(complete=True)` — 이때는 **아직 방출되지 않은 재개 발화 오디오까지 폐기**되어 복구 불가(Exp-177 Type B의 재확인). 배포에서 "전사가 안 되고 날아가는" 체감의 정체.

**무해 반증(경계조건)**: kor2는 같은 리셋이 5회 전부 발동했으나 전부 무해 — 침묵 전 문장이 이미 완전히 emit된 뒤라 버려진 것이 "이미 방출된 오디오"뿐이었음(`[TokenTrace]`로 확인). 즉 리셋 발동 자체가 아니라 **리셋 후 콜드스타트 + QG 연쇄**가 피해 조건.

**파생 경로 2건**(빈도 낮음, 별도):
- (auto 전용) 화자/언어 eager 재감지 실패 시 꼬리보존(kept≈1.5s) 없이 `kept=0.00s` 전체 폐기 — sbs1 R3 "이번 강연의", 오디오가 디코더에 도달 자체를 못 함.
- 컨텍스트 트림 직후 emit 시퀀스가 디코더가 이미 생성한 단어를 건너뜀(sbs1 R1/R5 "사령관은") — 커밋 diff 재동기화 버그, 원인 코드 미특정.

**두 버그의 교차**: 콜드스타트 직후는 디코더 attention이 자주 정체(새 토큰 0개 배치)해 hold-retry 고갈이 가속 — kor3 서두 "해역 함대 사이" 4~5/5 유실은 BUG A 상태가 BUG B 발동률을 끌어올린 겹침 사례.
