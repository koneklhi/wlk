## 1. 경로 역할 (불변)

- **경로 C (VBCable 루프백)** — **1차 정량 성능 기준**. 실제 오디오 파이프라인을 거치므로
  문장 분리 F1·WER의 채택/기각이 여기서 결정된다.
- **경로 A (`test_client.py`)** — 빠른 개발 스모크(코드 변경이 회귀를 냈는지). 성능 판정 기준 아님.
- **경로 B (마이크 직접)** — 정성 평가(확정 색상 전환·한영 인식·체감 지연).

(ROADMAP.md Phase 2 / CLAUDE.md §3.3·§5 / docs/TESTING.md와 일치.)

## 2. 성공 기준 (ROADMAP 본문 기준)

채택 조건(모두 충족):
1. **경로 C** 문장 분리 F1 ≥ 0.7(1차), 이상적으로 ≥ 0.8. sbs1·ytn1 균형.
2. **경로 C** WER이 경로 C 베이스라인 대비 개선 또는 유지(회귀 ≤ +5%p).
3. pytest 전부 통과.
4. 삽입 아티팩트가 전사 출력/경로 B 점검에서 악화되지 않음.

기각/과적합 가드:
- sbs1·ytn1 중 하나라도 직전 채택 대비 F1 −0.05 이상 하락 → 기각.
- 두 파일 F1 격차가 과도하게 벌어지면 일반화 실패로 간주.
- 치환 오류("육군"→"6군") 기인 WER은 모델 한계 → 추적하지 않고 기록만.

## 3. Phase 0 — 측정 신뢰성 확보 (먼저, 비협상)

> 지표가 깨져 있으면 이후 모든 실험이 노이즈다. 이 세션의 주 작업이 여기다.

- **0a. 경로 A `speed=0` 전사 절단 검증** — 같은 파일을 `speed=0` vs `speed=1.0`로 돌려
  전사 커버리지 비교. 절단이 `speed` 탓이면 eval 표준 설정 고정. (경로 A는 스모크용이지만,
  절단 현상 자체가 측정 신뢰성 진단의 출발점이다.)
- **0b. 참조↔오디오 정합** — `test_data/*.txt`가 실제 mp3 발화와 일치하는지 확인, 불일치 시 트림.
  `test_data/ytn1.trimmed.bak`에 이전 트림 시도가 보관돼 있으나, 트림 여부는 0a 결과 확인 후 확정한다.
- **0c. 경로 C 가동** — VBCable 드라이버 + `playwright install chromium` + `eval.py --paths C` 디버깅
  → 첫 성공 벤치(경로 C 베이스라인) 확보. 이 수치가 이후 모든 채택/기각의 기준점.

Phase 0 완료 기준: 전사가 오디오 전체를 커버(또는 참조 트림으로 정합) + 경로 C 베이스라인 1회 기록.

## 4. Phase 1 이후 (Phase 0 후 착수, 자동 세션과 분담)

레버리지·리스크 순. 각 변경 TDD 유닛테스트 → 경로 C eval → 채택조건 충족 시에만 채택.
이월된 하드 사실(PHASE2_EXPERIMENTS.md "이월된 사실")을 출발점으로:

- recall 향상(F1 0.7→0.8): 언어 전환 경계(`detected_language`), Whisper 세그먼트 경계,
  한국어 종결어미 일반화(특정 단어 하드코딩 금지, 규칙 기반).
- insertion 감소(WER 유지): cross-batch stateful 반복 필터(`_filter_repetitions`는 현재 배치 내부만 동작).
- 정성 마무리: 경로 B 확정 색상·한영 인식·체감 지연, 코드스위칭 단어유실 점검.
