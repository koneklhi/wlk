# 설계 문서: `/log-session` — 세션 기록 명령어

**날짜**: 2026-05-22  
**상태**: 설계 완료, 구현 대기

---

## 1. 목적

각 Claude Code 세션 종료 시 해당 세션의 대화 내용을 구조화된 마크다운 파일로 저장한다. 세 가지 용도를 동시에 충족한다:

1. **개인 회고/복기** — "오늘 뭔 했지?"를 나중에 빠르게 확인
2. **프로젝트 히스토리 축적** — 어떤 결정을 왜 내렸는지 장기 맥락 보존
3. **다음 세션 Claude 컨텍스트 제공** — 새 세션 시작 시 이전 논의 빠르게 주입

---

## 2. 저장 위치 및 파일명

- **저장 디렉토리**: `.omc/session-logs/`
- **파일명 규칙**: `YYYY-MM-DD_HHmm_<유형약자>_<주제-슬러그>.md`

| 유형 | 약자 | 예시 파일명 |
|------|------|------------|
| 개발 (Development) | `dev` | `2026-05-22_1430_dev_문장-확정-로직.md` |
| 질문/답변 (Q&A) | `qa` | `2026-05-22_1115_qa_폐쇄망-패키징.md` |
| 탐색·설계 (Exploration/Design) | `exp` | `2026-05-22_0930_exp_평가-파이프라인-설계.md` |
| 혼합 (Mixed) | `mix` | `2026-05-22_1600_mix_성능-분석-및-수정.md` |

---

## 3. 세션 유형 자동 감지

명령어 실행 시 Claude가 다음 기준으로 세션 유형을 자동 판단한다:

1. **개발 세션** — 파일 수정/생성, 코드 변경, 디버깅, 테스트 실행이 포함된 경우
2. **Q&A 세션** — 코드 변경 없이 질문·답변 중심, 개념/도구/라이브러리 설명 위주
3. **탐색·설계 세션** — 브레인스토밍, 아키텍처 토론, 계획 수립, 문서 설계
4. **혼합 세션** — 위 유형 2개 이상이 실질적으로 섞인 경우

---

## 4. 출력 구조 (3층 레이어드)

모든 유형에 공통으로 **한눈에 보기 + 상세 내용 + 다음 세션** 3층 구조를 적용한다. 상세 내용의 섹션만 유형에 따라 달라진다.

### 4.1 공통 상단: 한눈에 보기

```markdown
## 한눈에 보기

**세션 유형**: 개발 | Q&A | 탐색·설계 | 혼합  
**핵심 결정/답변**: (한 줄 요약)  
**변경 파일 목록**:  
- `경로/파일.py` — 수정: 한 줄 설명  
- `경로/파일2.py` — 신규  
```

*코드 변경이 없는 세션에서는 "변경 파일 목록" 섹션을 생략한다.*

---

### 4.2 유형별 상세 내용

#### 개발 세션 (dev)

```markdown
## 상세 내용

### 1. 문제 정의
(어떤 버그/요구사항/이슈였는가)

### 2. 분석 과정
(Claude의 사고 방식, 검토한 여러 옵션, 기각 이유)

### 3. 결정 근거
(왜 이 방안을 선택했는가, 트레이드오프)

### 4. 구현 내용

**변경 파일: `경로/파일.py`**
```diff
- 이전 코드
+ 새 코드
```
(또는 변경의 의미를 설명하는 코드 스니펫)

### 5. 결과 & 검증
(수행 결과, 테스트/eval 결과, 잔여 이슈)
```

#### Q&A 세션 (qa)

```markdown
## 상세 내용

### 질문 배경
(왜 이 질문이 필요했는가)

### 핵심 질문과 답변
**Q**: (질문)  
**A**: (Claude의 답변 요약)

### 후속 구체화
(이어진 질문/답변으로 어떻게 이해가 깊어졌는가)

### 최종 이해 / 결론
(이 세션 후 도달한 최종 이해 또는 결정)
```

#### 탐색·설계 세션 (exp)

```markdown
## 상세 내용

### 탐색 주제
(무엇을 탐색/설계하려 했는가)

### 발견사항
(코드베이스 분석, 문서 검토, 제약 발견 등)

### 토론 요약
(제안된 접근법들, 트레이드오프 비교)

### 결론 / 결정 사항
(최종으로 합의된 방향, 채택/기각 사유)

### 보류 사항
(결정 못 한 것, 추가 정보가 필요한 것)
```

#### 혼합 세션 (mix)

```markdown
## 상세 내용

(시간 순서로 파트를 구분해 각 파트에 해당 유형의 섹션 구조를 적용한다)

### 파트 1: [개발/Q&A/탐색·설계]
...

### 파트 2: [개발/Q&A/탐색·설계]
...
```

---

### 4.3 공통 하단: 다음 세션을 위해

```markdown
## 다음 세션을 위해

**미결 사항**:
- [ ] (해결하지 못한 이슈)

**이어서 할 것**:
- (다음 작업 목록)

**열린 질문**:
- (아직 답이 없는 질문들)
```

*미결 사항, 이어서 할 것, 열린 질문 중 해당 없는 항목은 생략한다.*

---

## 5. 명령어 실행 절차

Claude가 `/log-session` 호출 시 따를 순서:

1. 현재 세션 대화 전체를 검토한다
2. 세션 유형을 자동 감지한다 (§3)
3. 오늘 날짜 + 현재 시각을 기준으로 파일명 결정 (`YYYY-MM-DD_HHmm_<유형>_<주제>.md`)
4. `.omc/session-logs/` 디렉토리가 없으면 생성한다
5. §4 구조에 따라 마크다운을 작성한다
   - 코드 변경이 있으면 git diff 또는 핵심 스니펫을 포함한다
   - 의미 없는 섹션은 생략한다 (단, 한눈에 보기와 다음 세션은 항상 포함)
6. 파일을 저장하고 경로를 출력한다
7. 사용자에게 수정/추가할 내용이 있는지 확인을 구한다

---

## 6. 비고

- `.omc/session-logs/`는 `.gitignore`에 추가 여부를 사용자가 결정 (기본: 개인 기록이므로 제외 권장)
- 파일명의 주제 슬러그는 Claude가 세션 내용을 보고 3~4 단어로 자동 생성
- 단일 파일 분량이 너무 클 경우 (예: 장시간 혼합 세션) 파트별로 섹션을 분리해 가독성 유지
